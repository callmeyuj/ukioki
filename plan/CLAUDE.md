## 模块定义

**订阅计划（名义订阅，实质是价格计算器）**：消费者确定固定包数 → 自由分配口味 → 按包数套用折扣阶梯 → 得出**参考预算**。

> ⚠️ 定位澄清（2026/09/08 用户明确）：虽然叫"订阅"，但**不含配送周期、不含订阅管理、不含支付**。V1 就是一个"帮我 plan 好参考预算"的计算器，目前先做到这个地步。

**定位**：uki oki 品牌官网 P0 功能模块，路径 `/plan/`，与热量计算器（`/calories/`）平级、独立运行。

**运行环境约束**：网站跳转场景主要在微信内，必须兼容微信生态（微信内置浏览器、小程序 webview 容器）——技术选型与 calories/ 一致（纯前端、无框架），避免使用微信 webview 不支持的 API（分享逻辑需按微信环境适配）。

## 核心业务逻辑

### 计算主流程（2026/09/16 更新：锚点 + 天数维度 + 平均口径 + 热量校验 + 配送免邮）

```
⓪ 宠物类型：犬默认选中；猫置灰不可选 + 备注"敬请期待/即将上线"（决策 #28）
① 入口（两条路，2026/09/16 修订：正向跳转改为回程机制）
   a. 手动输入每日包数；不知道 → 引导按钮"先去算热量"跳 calories/?from=plan&pet=dog
      → calories/ 对该来源跳过 Step 0 犬猫选择，直接从体重输入开始（犬锁定，决策 #29）
      → 算完后喂食量页右侧按钮"🛒 前往商城"替换为"↩ 返回订阅计划"（仅检测到 from=plan 时，版式不变）
      → 点击回跳 plan/?pet=dog&packs=平均每日包数&kcal=目标热量（MER × 0.85）
   b. 直接手填每日包数（无目标热量参数 → 无热量校验）
② 锚点卡片（参考方案）：选天数（30/60/90 快捷档 或 自定义输入）
   → 参考总包数 = ⌈每日包数 × 天数⌉（向上取整）
   → 用户可"一键采用"锚点，或完全自由修改
③ 用户确定：固定总包数（≥30 包起订）
   → 系统同步显示免邮额度：⌊总包数 ÷ 30⌋ 次
④ 用户选择：配送次数（与免邮额度实时对比）
   → 次数 ≤ 额度：免运费；次数 > 额度：运费提示"请联系客服"
⑤ 用户分配：各口味的包数（自由搭配，合计 = 总包数）
⑥ 热量校验（仅回程路径 a，即 URL 带 kcal 参数）：按实际口味组合算加权热量
   → 显示"当前搭配日均摄入 ≈ X kcal，建议 Y kcal（偏差 ±Z%）"
   → 软提示不阻断，用户可自行微调分配
⑦ 价格计算：各口味包数 × 单价 → 小计 → 按总包数套用折扣阶梯（整单单一折扣率）
⑧ 输出：参考预算（折后总价 + 明细 + 运费结论）
   → 结果区唯一动作：保存/下载方案快照（长按保存/转发，兼作客服沟通介质）
```

**锚点策略说明**：参考方案只做锚点、不强制（"锚点 + 自由"混合思路），同时照顾需要指导的新客和心里有数的老客；天数维度与远期"按订阅时长折扣"的设想兼容——将来折扣规则若改按时长，`PLAN_RULES` 直接消费同一个天数字段，不动页面结构。

**每日包数口径（2026/09/16 确认）**：采用**平均热量口径**（犬 140 / 猫 119 kcal/包），即 `每日包数 = MER × 0.85 ÷ 平均单包热量`，与 calories/ 喂食量表"平均数据"行及分享快照口径完全一致。口味热量差异（犬 121~154 kcal）导致的实际摄入偏差（约 ±10~14%）由步骤 ⑤ 的热量校验软提示补足，不在锚点层面追求精确。

### 与热量计算器的关系

```
calories/ 输出：喂食量表按口味逐行给出包数 = (MER × 0.85) ÷ 该口味单包热量（0.5 步进取整），
              最后一行"平均数据"（犬 140 / 猫 119 kcal/包）即 plan/ 采用的口径
回程参数：plan/?pet=dog&packs=平均每日包数&kcal=目标热量（MER × 0.85）
plan/ 用途：平均每日包数作为"确定总包数"的参考依据（如：每日 2.5 包 → 30 天约 75 包）
```

**联动机制（2026/09/16 确认，决策 #26/#27/#29）**：

- **正向入口：不做**。calories/ 保持原版工具属性，不主动引流 plan/；plan/ 的曝光交给未来官网主页（P1）、小程序、公众号菜单
- **回程机制：条件按钮替换 + 跳过犬猫选择**。plan/ 引导按钮跳 `calories/?from=plan&pet=dog`；calories/ 检测到参数后**跳过 Step 0**（state.petType 锁定为 dog，直接从体重输入开始），喂食量页右侧按钮由"🛒 前往商城"**替换**为"↩ 返回订阅计划"（按钮数量与版式不变），点击携带 `pet/packs/kcal` 回跳 plan/。**直接打开 calories/ 的普通用户零感知**（Step 0 照常、商城按钮照常，代码执行路径一行不变）
- 回程冲突已消解：calories/ 内无法选猫，回传 pet 恒为 dog（参数保留以兼容未来猫上线）
- 猫用户：无独立落地页——plan/ 第 0 步置灰猫选项 + "敬请期待/即将上线"备注即承载告知（决策 #28 取代 #20 的落地页方案）

> ⚠️ 实现提示：回程机制需改动 calories/（读 URL 参数 + 跳过 Step 0 流程分支 + 商城按钮条件替换为回程按钮 + 拼回跳链接，预计 30~40 行；注意 `restart()` 重新计算时须保持犬锁定、从体重步开始），按 harness 规范做影响范围评估 + 回归测试（正常入口全流程 + from=plan 链路各跑一遍），calories/ 版本号相应递增；方案设计阶段细化。

**折扣阶梯（2026/09/16 确认，V1 按总包数分档）：**

| 档位 | 总包数区间 | 折扣率 |
|------|-----------|--------|
| 起订门槛 | < 30 | 不可下单（提示"30 包起订"） |
| 1 | [30, 90) | 0.85 |
| 2 | [90, 150) | 0.80 |
| 3 | [150, 210) | 0.75 |
| 4 | ≥ 210 | 0.70 |

- **套用方式**：整单单一折扣——总包数落在哪一档，全部包数按该档折扣率计价（非分段累进）
- **边界规则**：区间左闭右开，210 包整享 0.70（档位 4 为 ≥210）
- **凑单提示**：不做（保持页面简洁，2026/09/16 确认）
- ⚠️ 后续可能调整档位（增删档位、修改边界/折扣率），也可能改为**按订阅时长**的折扣阶梯
- **设计约束**：商业规则必须做成**配置驱动、可插拔**——统一的 `PLAN_RULES` 常量对象（原名 `DISCOUNT_RULES`，因新增运费规则升级命名），形如：

```js
const PLAN_RULES = {
  minPacks: 30,               // 起订门槛
  packsPerFreeDelivery: 30,   // 每满 30 包免邮 1 次（运费规则）
  tiers: [                    // 折扣档位：增删档位只改这里
    { min: 30,  max: 90,   rate: 0.85 },
    { min: 90,  max: 150,  rate: 0.80 },
    { min: 150, max: 210,  rate: 0.75 },
    { min: 210, max: null, rate: 0.70 },  // null = 无上限
  ],
};

// 运行时：
// 折扣率   = 查 tiers（按总包数落档）
// 免邮次数 = Math.floor(总包数 / packsPerFreeDelivery)
```

切换折扣维度（包数 → 时长）时只改配置和少量计算函数，不动页面结构。

### 运费规则（2026/09/16 确认，#8 配送费已解决）

**核心公式**：`免邮次数 = ⌊总包数 ÷ 30⌋`（每满 30 包得 1 次免邮，向下取整）

| 总包数 | 免邮次数 |
|--------|---------|
| 30（起订） | 1 |
| 75 | 2 |
| 90 | 3 |
| 150 | 5 |
| 210 | 7 |

> 边界：89 包 = 2 次（不满 90 不算 3 次）。免邮次数由总包数**线性推导**，与折扣档位表无关（档位边界 30/90/150/210 与 30 的倍数网格不重合），故不并入 tiers，而是 `PLAN_RULES` 的独立字段。

**交互**：用户**自选配送次数**，系统实时对比免邮额度：
- 所选次数 ≤ 免邮额度 → **免运费**，参考预算 = 折后商品价（完整确定）
- 所选次数 > 免邮额度 → 预算照常显示折后商品价，运费位置提示**"保存方案快照后发送给客服咨询运费"**（软引导，不阻断计算；快照 = 沟通介质，见决策 #24/#25）

**设计要点**：V1 纯前端不碰地址/重量等不可控维度，运费问题被"配送次数"规则转化为确定性判断；`packsPerFreeDelivery` 配置化，政策调整只改数字。
