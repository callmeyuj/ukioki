## 模块定义

**订阅计划（名义订阅，实质是价格计算器）**：消费者确定固定包数 → 自由分配口味 → 按包数套用折扣阶梯 → 得出**参考预算**。

> ⚠️ 定位澄清（2026/09/08 用户明确）：虽然叫"订阅"，但**不含配送周期、不含订阅管理、不含支付**。V1 就是一个"帮我 plan 好参考预算"的计算器，目前先做到这个地步。

**定位**：uki oki 品牌官网 P0 功能模块，路径 `/plan/`，与热量计算器（`/calories/`）平级、独立运行。

**运行环境约束**：网站跳转场景主要在微信内，必须兼容微信生态（微信内置浏览器、小程序 webview 容器）——技术选型与 calories/ 一致（纯前端、无框架），避免使用微信 webview 不支持的 API（分享逻辑需按微信环境适配）。

## 核心业务逻辑

### 计算主流程（2026/09/08 确认）

```
① 参考输入：每日建议包数（来自 calories/ 跳转 或 手动输入）
② 用户确定：固定总包数
③ 用户分配：各口味的包数（自由搭配，合计 = 总包数）
④ 价格计算：各口味包数 × 单价 → 小计 → 按总包数套用折扣阶梯
⑤ 输出：参考预算（折后总价 + 明细）
```

### 与热量计算器的关系

```
calories/ 输出：每日建议喂食包数 = (MER × 0.85) ÷ 单包热量（0.5 步进取整）
plan/ 用途：作为"确定总包数"的参考依据（如：每日 2.5 包 → 30 天约 75 包）
```

**折扣阶梯**：⏳ 暂未确定

- **设计约束**：折扣机制必须做成**配置驱动、可插拔**（如独立的 `DISCOUNT_RULES` 常量对象），切换折扣维度（包数 → 时长）时只改配置和少量计算函数，不动页面结构

## 技术规划（草案）

- 纯前端（HTML + CSS + JS），与 calories/ 相同技术栈，零依赖
- 引用共享资源：`../shared/brand.css` → `../shared/components.css` → `style.css`；`../shared/utils.js` → `script.js`
- 可复用的共享工具：`roundToHalf()`、`formatPacks()`、`isMobile()`、`toggleSelection()`、`debounce()`（算价输入防抖）
- 文件结构（开发时创建）：

```
plan/
├── index.html      # 页面结构
├── style.css       # 模块专属样式
├── script.js       # 订阅计算逻辑
├── CLAUDE.md       # 本文件
└── CHANGELOG.md    # 模块版本记录
```
